## 工作方式

Codex Autoresearch 把实验组织成一个闭环：

```text
检查当前证据
→ 修改一个聚焦点
→ 运行验证命令
→ 指标改善则保留，否则回退
→ 记录结果并继续
```

它适合优化测试失败数、覆盖率、延迟、内存占用、模型损失、预测误差等能由稳定命令计算的指标。通过 Git 提交保存有效实验，并丢弃没有改善或破坏回归保护条件的改动。

## 使用前提

- 仓库处于干净、具名的 Git 分支；
- 指标命令可重复运行并输出有限数值；
- 已明确指标方向、目标值、修改范围和最大迭代数；
- 重要但未被主指标覆盖的行为有独立 guard 命令；
- 数据版本、随机种子、环境和评价脚本已经固定。

## 在 Codex 中调用

```text
$codex-autoresearch

目标：把 `python scripts/evaluate.py` 输出的 `rmse` 降到 0.15 以下。
允许修改：src/model.py、configs/experiment.yaml。
指标解析：JSON 键 rmse，越低越好。
回归保护：python -m pytest tests。
最多迭代：20。
运行方式：前台。
```

## 科研论文中的用法

该 Skill 适合运行论文背后的可复现实验，而不是直接评价“论文质量”。每轮实验应保存配置、代码提交、数据版本、指标输出和失败原因，最终再由写作流程依据真实结果生成方法与结果章节。

## 风险与边界

- 不适合不可量化的理论判断、开放式综述或主观文字质量；
- 指标可能被投机性优化，必须配置回归保护并人工检查代表性；
- 自动回退和提交依赖 Git，运行前应保护用户现有改动；
- 不应自动扩大允许修改的文件范围，也不应绕过计算成本、数据授权或伦理限制。
